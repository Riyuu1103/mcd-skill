# 接聊天机器人（可选）

> 这不是必需的一步。**不接机器人，你自己跟 AI 说话也能点餐**（见《使用指南》）。
> 这份文档是给「想把点餐挂到 QQ / Telegram / 微信机器人上」的人看的。
> 只要机器人能执行 shell 命令，就能调这个 CLI。

## 1. 为什么要这么接

聊天机器人**没有手**，它拿不到你的手机，也付不了款。所以正确的分工是：

```
用户说话 → 机器人查门店/菜单/券 → 算价 → 报给用户 → 用户说「确认」
        → 机器人下单 → 把【支付链接】发回来 → 用户自己扫码付款
```

**付款这一步永远留在人这一侧。**

## 2. 机器人需要的三个能力

| 能力 | 对应 | 说明 |
|---|---|---|
| 执行命令 | `exec` / `shell` 工具 | 跑 `node scripts/mcd.mjs ...` |
| 记住上下文 | 多轮会话 | 确认前的算价结果要留到确认之后 |
| 发消息 | QQ / TG / 微信 通道 | 把摘要和支付链接发出去 |

## 3. 以 OpenClaw 为例（可选，仅作参考）

> 任何有 shell 权限的机器人都适用，这里只是拿一个具体框架演示落地步骤。

### 3.1 机器人工作区放一份操作手册

把本文件的「5. 机器人侧规则」抄成
`~/.openclaw/workspace/mcd.md`（路径按你的机器改），
机器人每一轮都会重读它。

### 3.2 在人设文件里加一行指针

在 `workspace\AGENTS.md` 里加：

```markdown
## 麦当劳点餐
需要点麦当劳时先读 `mcd.md`，命令统一走
`node "<仓库路径>/scripts/mcd.mjs" ...`。
下单前必须把 门店/商品/实付 报给我并等我说「确认」；付款我自己扫。
```

**不要**把整份手册塞进 `AGENTS.md`——它每轮都进上下文，越长越慢。

### 3.3 验证：不惊动 QQ 的探针

```bash
openclaw agent --agent main --session-key "agent:main:mcd-probe" \
  -m "麦当劳点餐的命令是什么？下单前要做什么？"
```

不加 `--deliver` 就不会往 QQ 发东西。

## 4. 命令模板（直接抄）

```bash
MCD='node scripts/mcd.mjs'

# 0) 看一眼局面：积分 / 可领券 / 默认门店 / 上一单
$MCD home

# 1) 服务器时间
$MCD now

# 2) 找门店（只在没有默认门店或要换店时）
$MCD stores --city 上海 --keyword 中山北路3663号
$MCD profile use-store 1

# 3) 菜单
$MCD menu --grep 巨无霸

# 4) 算价（自动挑最省的券，输出已经是元）
$MCD price --item "巨无霸:1" --item "中薯条:1"

# 5) 外送 / 预约
$MCD price --mode delivery --item "巨无霸:1"
$MCD price --item "巨无霸:1" --at "2026-11-02 18:00"

# 6) 下单（用户确认之后；不带 --confirm 会被拦下来，这是故意的）
$MCD order --item "巨无霸:1" --confirm

# 7) 上一单再来一份
$MCD reorder
$MCD reorder --confirm

# 8) 查单 / 取消
$MCD history 5
$MCD order-status <orderId>
$MCD cancel <orderId> --reason 3 --confirm
```

## 5. 机器人侧的规则（写进它的人设里）

1. **一次只问一件事**。缺地址就问地址，缺门店就问门店。
2. **确认话术固定五段**：门店 / 商品与数量 / **套餐可换项** / 实付金额 / 取餐或送达时间。
   用户回「确认」「好」「下单」任一即视为同意。
3. **点套餐必须先 `detail`**，把能换的和差价主动说出来（哪怕用户没问）。
4. **每次变动重报总价**：商品/规格/数量/券/取餐方式任一变化，重新 `price`，
   报新的 `▶ 实付`，并说明比上一版多/少多少。
5. **不许自己编地址、电话、联系人**。
6. **支付链接单独一行**，不要缩写、不要包代码块。
7. **超时先查单**：`history` / `order-status`，别直接重下。
8. **积分和券要报清**：这单省了多少、积分还剩多少。
9. **不在群里点餐**，除非用户明确要求——群里发支付链接等于把二维码摊给所有人。

## 5.1 她为什么会慢（以及怎么快一点）

实测：**一次只回答、不调工具的回合 ≈ 37 秒**（冷启动会话）。
慢的不是这个 skill，是 AI 助理那一层（网关准备 + 会话加载 + 系统提示拼装），
这台机器上单轮准备就 20~40 秒。命令行本身一次调用只要 **0.6~1.5 秒**。

所以能做的优化是**减少回合数、减少她自己的措辞加工**：

| 做法 | 效果 |
|---|---|
| 一条命令出结果（`price` 内部已合并 5 步） | 少 3~4 次工具调用 |
| 用 `--brief` 拿三行成品，直接转发 | 少一次"把结果改写成人话" |
| `home` 代替分别查积分/券/订单 | 1 次代替 4 次 |
| 别让她先 `tools` / `schema` 探索 | 那些是给她不认识接口时用的 |

**别人用同一个 skill 不会因为 skill 而慢**——skill 本身每步不到 1.5 秒；
但如果他们的 agent 本身准备阶段就慢（比如同款本地网关），体验同样是几十秒一轮。


## 6. 实际对话长什么样

```
用户: 给我点个巨无霸套餐 送到家
机器人: 送到「XX 小区 X 栋 X 单元」，可送门店是「麦当劳(中山北路店)」，
        30 分钟送到。确认这个地址吗？
用户: 确认
机器人: 巨无霸四件套 ×1  ¥33.50
        （小食可换：麦旋风 +¥1 / 玉米杯 +¥0）
        配送费 ¥6.00 ｜ 券抵 ¥5.00
        实付 ¥34.50 ｜ 预计 30 分钟送达
        —— 下单吗？
用户: 下单
机器人: 已下单，订单号 1234567890
        https://...
        付完告诉我，我盯着出餐。
```

## 7. 机器人会遇到的真问题

| 问题 | 原因 | 处理 |
|---|---|---|
| 链接被 QQ 折叠/截断 | 长 URL | 单独一行发，别夹在句子里 |
| 「确认」之后找不到上一步 | 上下文被压缩 | 让她重新 `price` 一次再确认 |
| 报了 100 倍的价格 | 直接给了 `calculate-price` 的原始返回 | 用 `price` 命令，它已经换算成元 |
| 下单报错「beCode 必填」 | 到店自取不用传，其它场景要传 | 用 `--mode` 切换，别手拼参数 |
| 一单扣了两次 | 超时重试 | 重试前先 `history` |
| 她说「已下单」但其实被拦了 | 忘了 `--confirm` | 看退出码 3 和「已拦截」提示 |
